# 05 — The dashboard

"Very, very beautiful" is an explicit requirement (G8). This page should be good enough that the user sets it as
their browser home page / new-tab page and genuinely enjoys it. Treat visual design as core scope: budget real time
for it, iterate with screenshots, and do not ship a generic admin-template look.

## Principles

1. **A jumping-off point, not a control panel.** The primary action is *go to the thing*. Everything else is
   secondary.
2. **Instant.** Local data, so the page should paint fully in well under 200 ms. One `GET /api/state` call renders the
   whole page; no spinners on the main view. Live updates arrive over SSE.
3. **Calm.** Most of the time everything is fine or intentionally off. The page should feel quiet; only `down` is
   alarming. Never paint stopped-on-purpose things red (D12).
4. **Dense but legible.** Many apps visible at once without scrolling on a laptop screen.
5. **Keyboard-first.** It is used dozens of times a day; it must be faster than remembering a URL.
6. **Never needs hand-maintenance** to be accurate (G5): the observed tray turns reality into one-click registrations.

screen is optional (some users only want the proxy + CLI). The bookmarks section is hidden when there are no
bookmarks; the observed tray is hidden when empty.

## App card

Anatomy, top to bottom:

- **Thumbnail** (see below), with the framework/app icon overlaid in a corner.
- **Name** (from YAML / package.json), and for worktree siblings **`repo @ branch`** in smaller type.
- **Address** — the primary click target. Fronted mode: `review.localhost` (protocol omitted for display). Direct
  mode: `localhost:5622`. A copy button appears on hover/focus.
- **Uptime bar** for the last 24 h, with the uptime % and current p50 latency to its right.
- **State indicator** — colour **and** shape **and** text (accessibility; never colour alone):
  `● healthy`, `▲ unhealthy`, `■ down`, `○ stopped`, `◌ unknown`, `◐ starting`.
- Subtle badges, only when relevant: `orphaned` (PPID 1, not managed), `exposed` (bound to `0.0.0.0`), `managed`
  (launchd service), source (`declared` / `discovered: <adapter>`), config error.

Interactions:
- Click / Enter → open the app (same tab by default; ⌘/Ctrl-click or ⌘/Ctrl-Enter → new tab).
- A secondary affordance (e.g. `…` or `i`) opens the **detail drawer**.

## Detail drawer

- Full identity: project directory (tildified), git repo / branch / last commit, framework, PID, start time, bind
  address, the command that started it, parent process.
- Uptime with 24 h / 7 d / 90 d toggle; latency chart (p50/p95).
- Config: the YAML file path with an "open in editor" link (`vscode://file/…` or `$EDITOR` via CLI hint), plus inline
  editing of common fields through the API.
- For managed services (v1): Start / Stop / Restart, last exit code, and a live log tail.
- Deep links from `links:`.
- Any YAML error for this app, with file and line.

## Observed tray ("Found running — not yet named")

One row per observed listener: port, best-guess name, `dir @ branch`, age ("up 9 days"), `orphaned` when PPID is 1,
`<title>` from the HTTP sniff. Actions: **Claim** (a small inline form: slug pre-filled from the package name,
display name, `expected`), **Ignore** (by port / by process / by directory), **Open**.

A collapsed "other listeners" disclosure lists non-HTTP listeners for completeness.

## "Lost at last reboot" notice (v1)

A dismissible banner after a reboot, listing what was running before and is gone now, each with *Restart once*,
*Make it a service* and *Dismiss*. See `04`.

## Bookmarks

Visually distinct from apps: they are inert, so they should be lighter-weight — **favicon-led chips** in labelled
groups (one group per `bookmarks/<group>.yaml`), sorted by `order`. Users pattern-match on logos here, not status.

- Favicons fetched once and cached (`cache/favicons/`); fall back to a monogram tile coloured from a hash of the
  hostname.
- Optional per-link `description` as a tooltip.
- Groups collapsible; state remembered in the YAML (`collapsed`) so it is the same everywhere.
- Inline add/edit through the API, but files remain the truth.
- Remote bookmarks are not health-checked by default (Q-BOOKMARK-HEALTH).

## Uptime bar

The signature visual, in the style popularised by status pages (Gatus, Uptime Kuma):

- 48 thin vertical bars covering the last 24 h (30 minutes each) on cards; 7 d / 90 d use the hourly / daily rollups
  in the drawer.
- Each bar coloured by the period's worst significant state: healthy → positive tone; any unhealthy → warning; any
  down → alarm. `stopped` periods are drawn in a neutral, quiet tone (e.g. low-contrast hatching) — visibly different
  from both up and down. **No data** (daemon not running) is an empty outline.
- Uniform height; small gaps between bars; rounded ends. Hover shows the time range, uptime % and p50 latency.
- Uptime % excludes `stopped` time.

## Thumbnails (D13)

Three tiers. Each card uses the best available.

1. **Favicon + colour tile (default, v0).** Fetch the app's HTML once, parse `<link rel="icon">`,
   `apple-touch-icon` and the web-app manifest's icons; fall back to `/favicon.ico`; pick the largest. Extract a
   dominant colour (downscale, quantise, choose the most frequent sufficiently-saturated colour). Render a tile: a
   soft gradient from that colour with the icon centred. No icon → monogram on a colour derived from a hash of the
   slug. Zero extra dependencies (SVG favicons render via resvg; modern `.ico` files embed PNG frames that can be
   extracted directly). Instant and surprisingly effective for recognition.
2. **Real screenshots (opt-in, v2).** Headless Chromium via Playwright at 1280×800, waiting for network idle (capped at
   10 s), stored downscaled (~640×400) in `cache/thumbs/`. Re-shoot when the app restarts (PID change), every 6 h,
   or on demand. Only shoot `healthy` apps. Never shoot bookmarks. Playwright is **not** a hard dependency: `sj thumbs
   enable` installs Chromium into the data home (e.g. via `PLAYWRIGHT_BROWSERS_PATH`) and flips `thumbnails.mode`.
   Screenshots never leave the machine.
3. **Generated card (fallback, v2).** An SVG with the name, address, framework icon and `repo @ branch`, rendered to
   PNG with resvg and bundled fonts — exactly Local Review's approach:

   ```ts
   export function svgToPng(svg: string, zoom = 2): Buffer {
     fontPaths ??= Object.values(FONT_FILES).map((f) => path.join(FONT_DIR, f));
     const r = new Resvg(svg, {
       fitTo: { mode: 'zoom', value: zoom },
       background: '#ffffff',
       // only the bundled fonts: the same output on every machine and no slow system font scan.
       font: { fontFiles: fontPaths, loadSystemFonts: false, defaultFontFamily: 'Inter',
               sansSerifFamily: 'Inter', monospaceFamily: 'JetBrains Mono' },
     });
     return r.render().asPng();
   }
   ```

Serve thumbnails with ETags (`GET /api/apps/:slug/thumb`, 304 on match) and emit a `thumb` event when one changes.

## Keyboard

| Key | Action |
|-----|--------|
| `/` | Focus the filter (fuzzy over name, slug, host, port, dir, branch, bookmark titles) |
| `↑ ↓ ← →` | Move between cards/chips |
| `Enter` | Open; `⌘/Ctrl-Enter` new tab |
| `c` | Copy the focused item's URL |
| `i` | Open detail drawer |
| `Esc` | Clear filter / close drawer |
| `?` | Shortcut help |

Typing a filter that matches exactly one item and pressing Enter opens it — the "faster than remembering a URL" path.

## Ambient status (decided, D22)

- The tab title reflects trouble: `(1 down) Spaghetti Junction`; with several problems, count them all:
  `(2 down · 1 unhealthy) Spaghetti Junction`. When everything is fine the title is just the name.
- The page favicon is drawn dynamically (canvas → data URL) with a small status mark — calm when all is well, alarm
  when something is `down` — so a pinned tab shows status at a glance. Only `down` and `unhealthy` count; `stopped`
  never does (D12).
- Both update live from the SSE stream, so a background tab changes when an app falls over.

## Visual direction (decided, D23): British motorway signage

The name comes from Spaghetti Junction, the Gravelly Hill Interchange in Birmingham (junction 6 of the M6), famous for
its tangle of slip roads. The identity borrows the visual language of UK road signs, which is strong, beautiful
and instantly recognisable: deep blue panels, white rounded humanist lettering, generous spacing, route and junction
numbers in boxes. **Borrow the language, don't replicate signs.** The implementer should explore within this
direction (iterating with screenshots), then commit to it.

Ideas to explore:
- **Section headers as sign panels**: "APPS", "FOUND RUNNING", "BOOKMARKS" as blue panels with white lettering.
- **Ports as junction numbers**: the port rendered in a small boxed badge, like a junction-number plate (`5622`).
- **Hostnames as destinations**: the primary label, set in the large white display face.
- **Road classes as a quiet source cue** (optional): UK signs use blue for motorways, green for primary routes and
  white for local roads, which maps neatly onto managed services / declared apps / observed listeners. Keep it subtle;
  status colours must stay unambiguous and never be confused with source colours.

Typography and licensing: the official UK sign typefaces should not be bundled unless their licence clearly allows
it. Use a freely licensed (e.g. OFL) rounded humanist sans for display, Inter for UI text, and JetBrains Mono for
numbers. Inter and JetBrains Mono are already bundled in the sibling project Local Review under the OFL.

General constraints:
- **Dark-first** with a properly designed light mode (`dashboard.theme: auto`). In dark mode the sign blue is the
  accent and panel colour against a near-black background; in light mode, panels stay blue on a light background.
- Generous whitespace inside a dense grid; restrained motion (state changes fade, nothing bounces); no gradients for
  their own sake except in thumbnails.
- State colours must pass contrast in both themes and always be paired with shape and text.
- Numbers (ports, latency, percentages) in tabular/monospaced figures (JetBrains Mono is bundled in the sibling
  project).

## Empty and first-run states

- No apps declared yet: lead with the observed tray — "We found 4 web servers running. Name the ones you care about."
- Nothing running and nothing declared: a short explainer with the two commands that matter (`sj run …`, and the
  YAML path for adding an app by hand) and a link to the agent guide.
- Daemon unreachable (in fronted mode Caddy serves the fallback page): see `03`.

## Errors

YAML parse/validation errors appear in place — on the affected card, or as a banner for `config.yaml`/bookmark
files — with file path, line and message. Never a blank page.
