# 05 — The dashboard

"Very, very beautiful" is an explicit requirement (G8). This page should be good enough that the user sets it as
their browser home page / new-tab page and genuinely enjoys it. Treat visual design as core scope: budget real time
for it, iterate with screenshots, and do not ship a generic admin-template look.

## Principles

1. **A jumping-off point, not a control panel.** The primary action is *go to the thing*. Everything else is
   secondary.
2. **Instant.** Local data, so the page should paint fully in well under 200 ms. One `GET /api/state` call renders the
   whole page; no spinners on the main view. Live updates arrive over SSE.
3. **Calm.** Most of the time everything is fine or intentionally off. The page should feel quiet; only `down` is
   alarming. Never paint stopped-on-purpose things red (D12).
4. **Dense but legible.** Many apps visible at once without scrolling on a laptop screen.
5. **Keyboard-first.** It is used dozens of times a day; it must be faster than remembering a URL.
6. **Never needs hand-maintenance** to be accurate (G5): the observed tray turns reality into one-click registrations.

Sections, their order and their presence are controlled by `dashboard.sections` in `config.yaml`; the whole home
screen is optional (some users only want the proxy + CLI). The bookmarks section is hidden when there are no
bookmarks; the observed tray is hidden when empty.

## App card

Anatomy, top to bottom:

- **Thumbnail** (see below), with the framework/app icon overlaid in a corner.
- **Name** (from YAML / package.json), and for worktree siblings **`repo @ branch`** in smaller type.
- **Address** — the primary click target. Fronted mode: `review.localhost` (protocol omitted for display). Direct
  mode: `localhost:5622`. A copy button appears on hover/focus.
- **Uptime bar** for the last 24 h, with the uptime % and current p50 latency to its right.
- **State indicator** — colour **and** shape **and** text (accessibility; never colour alone):
  `● healthy`, `▲ unhealthy`, `■ down`, `○ stopped`, `◌ unknown`, `◐ starting`.
- Subtle badges, only when relevant: `orphaned` (PPID 1, not managed), `exposed` (bound to `0.0.0.0`), `managed`
  (launchd service), source (`declared` / `discovered: <adapter>`), config error.

Interactions:
- Click / Enter → open the app (same tab by default; ⌘/Ctrl-click or ⌘/Ctrl-Enter → new tab).
- A secondary affordance (e.g. `…` or `i`) opens the **detail drawer**.

## Detail drawer

- Full identity: project directory (tildified), git repo / branch / last commit, framework, PID, start time, bind
  address, the command that started it, parent process.
- Uptime with 24 h / 7 d / 90 d toggle; latency chart (p50/p95).
- Config: the YAML file path with an "open in editor" link (`vscode://file/…` or `$EDITOR` via CLI hint), plus inline
  editing of common fields through the API.
- For managed services (v1): Start / Stop / Restart, last exit code, and a live log tail. **Not built yet** (as of
  0.3.0): the API behind them is (`POST /api/apps/:slug/service/start|stop|restart`, `GET /api/apps/:slug/logs`),
  but `src/components/Drawer.tsx` has no controls; use `hallway start|stop|restart|logs`.
- Deep links from `links:`.
- Any YAML error for this app, with file and line.

## Observed tray ("Found running — not yet named")

One row per observed listener: port, best-guess name, `dir @ branch`, age ("up 9 days"), `orphaned` when PPID is 1,
`<title>` from the HTTP sniff. Actions: **Claim** (a small inline form: slug pre-filled from the package name,
display name, `expected`), **Ignore** (by port / by process / by directory), **Open**.

A collapsed "other listeners" disclosure lists non-HTTP listeners for completeness.

## "Lost at last reboot" notice (v1, **built**; D54)

A dismissible banner after a reboot, above the apps (`src/components/Lost.tsx`): a closed-door mark, "Lost at last
reboot (Mon 28 Sep 20:05): 6 apps", the line *Doors that closed while you were away*, and **Review** / **Dismiss**.
Review opens one row per item: the port plate, what it was, its state as mark + word + colour (`▯ not running` in the
warning tone; `● back` in the healthy tone once it's listening again), where it ran from (`~/Code/dir @ branch`), its
command, and **Restart once**, **Make it a service** and **Dismiss**. An item with no app says which `apps/<slug>.yaml`
starting it will write. A failure shows under the row in plain words, with the job's last log lines when it started
but didn't listen. When everything is back the banner turns calm ("all 6 are back") until dismissed. See `04`.

## Bookmarks

Visually distinct from apps: they are inert, so they should be lighter-weight — **favicon-led chips** in labelled
groups (one group per `bookmarks/<group>.yaml`), sorted by `order`. Users pattern-match on logos here, not status.

- Favicons fetched once and cached (`cache/favicons/`); fall back to a monogram tile coloured from a hash of the
  hostname.
- Optional per-link `description` as a tooltip.
- Groups collapsible; state remembered in the YAML (`collapsed`) so it is the same everywhere.
- Inline add/edit through the API, but files remain the truth.
- Remote bookmarks are not health-checked by default (Q-BOOKMARK-HEALTH).

## Uptime bar

The signature visual, in the style popularised by status pages (Gatus, Uptime Kuma):

- 48 thin vertical bars covering the last 24 h (30 minutes each) on cards; 7 d / 90 d use the hourly / daily rollups
  in the drawer.
- Each bar coloured by the period's worst significant state: healthy → positive tone; any unhealthy → warning; any
  down → alarm. `stopped` periods are drawn in a neutral, quiet tone (e.g. low-contrast hatching) — visibly different
  from both up and down. **No data** (daemon not running) is an empty outline.
- Uniform height; small gaps between bars; rounded ends. Hover shows the time range, uptime % and p50 latency.
- Uptime % excludes `stopped` time.

## Thumbnails (D13)

Three tiers. Each card uses the best available.

1. **Favicon + colour tile (default, v0).** Fetch the app's HTML once, parse `<link rel="icon">`,
   `apple-touch-icon` and the web-app manifest's icons; fall back to `/favicon.ico`; pick the largest. Extract a
   dominant colour (downscale, quantise, choose the most frequent sufficiently-saturated colour). Render a tile: a
   soft gradient from that colour with the icon centred. No icon → monogram on a colour derived from a hash of the
   slug. Zero extra dependencies (SVG favicons render via resvg; modern `.ico` files embed PNG frames that can be
   extracted directly). Instant and surprisingly effective for recognition. As built (D39), the daemon finds and
   caches the icon and the dashboard picks the colour from the image in a canvas, so the daemon needs no decoder.
2. **Real screenshots (opt-in, v2).** Headless Chromium via Playwright at 1280×800, waiting for network idle (capped at
   10 s), stored downscaled (~640×400) in `cache/thumbs/`. Re-shoot when the app restarts (PID change), every 6 h,
   or on demand. Only shoot `healthy` apps. Never shoot bookmarks. Playwright is **not** a hard dependency: `hallway thumbs
   enable` installs Chromium into the data home (e.g. via `PLAYWRIGHT_BROWSERS_PATH`) and flips `thumbnails.mode`.
   Screenshots never leave the machine. **As built (D56):** playwright-core is `npm install`ed into `cache/browser/`
   at `enable` time and loaded from there by path, Chromium's headless shell beside it; 1280×800 is drawn at half
   scale, so Chromium itself produces the 640×400 PNG. A screenshot is drawn as the **door's glass** (set in the
   panels' frame, clear of the knob, the number plate on top), and the drawer shows it as a preview.
3. **Generated card (fallback, v2).** An SVG with the name, address, framework icon and `repo @ branch`, rendered to
   PNG with resvg and bundled fonts — exactly Local Review's approach:

   ```ts
   export function svgToPng(svg: string, zoom = 2): Buffer {
     fontPaths ??= Object.values(FONT_FILES).map((f) => path.join(FONT_DIR, f));
     const r = new Resvg(svg, {
       fitTo: { mode: 'zoom', value: zoom },
       background: '#ffffff',
       // only the bundled fonts: the same output on every machine and no slow system font scan.
       font: { fontFiles: fontPaths, loadSystemFonts: false, defaultFontFamily: 'Inter',
               sansSerifFamily: 'Inter', monospaceFamily: 'JetBrains Mono' },
     });
     return r.render().asPng();
   }
   ```

   **As built (D55):** the card is a drawing of the door itself (paint, panels, knob, a brass plate with the address)
   with the name, a framework chip and `repo @ branch`, 640×400, in static instances of the dashboard's own faces
   (`assets/fonts/`). It is **not** the automatic fallback: judged on screenshots, a card on a door repeats the name
   printed under it and its plate is too small to read, so a door with no favicon keeps its monogram, and cards are the
   `thumbnails.mode: card` look (every door drawn as its card).

Serve thumbnails with ETags (`GET /api/apps/:slug/thumb`, 304 on match) and emit a `thumb` event when one changes.

## Keyboard

| Key | Action |
|-----|--------|
| `/` | Focus the filter (fuzzy over name, slug, host, port, dir, branch, bookmark titles) |
| `↑ ↓ ← →` | Move between cards/chips |
| `Enter` | Open; `⌘/Ctrl-Enter` new tab |
| `c` | Copy the focused item's URL |
| `i` | Open detail drawer |
| `Esc` | Clear filter / close drawer |
| `?` | Shortcut help |

Typing a filter that matches exactly one item and pressing Enter opens it — the "faster than remembering a URL" path.

## Ambient status (decided, D22)

- The tab title reflects trouble: `(1 down) Hallway`; with several problems, count them all:
  `(2 down · 1 unhealthy) Hallway`. When everything is fine the title is just the name.
- The page favicon is drawn dynamically (canvas → data URL) with a small status mark — calm when all is well, alarm
  when something is `down` — so a pinned tab shows status at a glance. Only `down` and `unhealthy` count; `stopped`
  never does (D12).
- Both update live from the SSE stream, so a background tab changes when an app falls over.

## Visual direction (proposed, D23): the hallway

> **Proposal, awaiting the author's approval** (Q-VISUAL-IDENTITY). Prototype against it and iterate with
> screenshots, but don't finalise a logo, display typeface or palette until it is approved. It replaces the previous
> direction, which was tied to the old name (see D23).

The product is the front door for everything you built; the dashboard is the **hallway** behind it: a calm, tidy,
well-lit corridor where every door is labelled. The feeling to aim for is *coming home and knowing where everything
is*. It should not feel like a control room, a server rack or a haunted house.

Moods to draw on (borrow the feeling, never the art):
- **The Wood between the Worlds** (*The Magician's Nephew*): a drowsy place full of identical pools, each leading to a
  different world, where you forget which pool is home. That is the original problem, many identical-looking dev
  servers and nobody remembering which is which. Hallway is the cure: every door has a number, a name and a picture.
- **A corridor of doors between worlds** (Apple TV+'s *Dark Matter*, 2024): rows of doors that all look alike. This
  is a warning as well as an image. The design must make doors *distinguishable* at a glance (thumbnail, name,
  `repo @ branch`), never a uniform grid of identical rectangles.
- **L-space** (Discworld): every library connects to every other. The hallway likewise connects every place you
  work, local apps through its doors and remote ones through the bookmarks by the front door.

The metaphor, mapped onto the existing UI:

| UI element | In the hallway |
|------------|----------------|
| App card | A **door**. The card *is* the door; its thumbnail or favicon tile is the door's paint, so each door looks different. |
| Port | The **door number**, on a small numeral plate in monospaced figures (`5622`). In fronted mode the hostname is the nameplate and the number is secondary. |
| `healthy` | Door **ajar**, with a sliver of warm light showing. |
| `stopped` | Door **closed**. Calm and neutral, like any closed door in a tidy house (D12). |
| `down` | Door **dark or boarded up**. The only alarming state. |
| `unhealthy` | Light **flickering** behind the door, a warning tone. |
| `starting` | Door **opening**, light coming up. |
| `unknown` | Door **in shadow**, drawn as an outline. |
| Observed tray | **Noises behind doors you didn't know were there.** The plain heading ("Found running — not yet named") stays primary; the imagery is for illustration and empty states. |
| Bookmarks | A **key hook or coat rack by the front door**: small chips hung in a row, lighter than the doors because nothing is behind them to check. |
| "Lost at last reboot" | **Doors that closed while you were away**, listed with a way to open each one again. |
| Header | The **front door / doormat**: the machine's name and the overall count. |

The door imagery *adds to* the state indicators in "App card" above (colour, shape and text) and never replaces
them. A user who never notices the metaphor must still read every state correctly.

Ideas to explore:
- A subtle **light-spill** gradient at a card's edge for `healthy` (warm) versus none for `stopped`. This is the one
  place a gradient carries meaning.
- **Door-number plates** for ports, in brass/amber on dark and dark on light.
- Section headings set like **painted signs on a wall** rather than admin-panel labels.
- A **floorboard or skirting rhythm** in the grid spacing, very quiet.
- An illustrated **empty state**: a short, empty, well-lit hallway with one door ajar and the first-run commands.

Keep the copy plain. The metaphor belongs in visuals, empty states and the odd light touch, not in every label:
"Claim", "Ignore", "Down" stay as they are. Never make a user decode a pun to understand a state.

Typography and licensing: use only freely licensed (e.g. OFL) fonts and check each licence before bundling. A warm
display face for nameplates, Inter for UI text, and JetBrains Mono for door numbers and other figures. Inter and
JetBrains Mono are already bundled in the sibling project Local Review under the OFL.

Brand constraints:
- Never copy any franchise's imagery, characters, typography or logos. *Narnia* and *Aslan* are trademarks: they may
  appear in a backstory or "Why the name" page, never in the branding (no lamp-posts or lions in the logo).
- The identity should still work if nobody recognises the references: it is a hallway first.

General constraints:
- **Dark-first** with a properly designed light mode (`dashboard.theme: auto`). Dark is a warm, dim corridor at night
  (warm near-black rather than blue-black, lamplight amber as the accent); light is a daylit hallway (warm off-white,
  muted wood tones). Door paint comes from each app's tile colour, toned down so status colours always stand out.
- Generous whitespace inside a dense grid; restrained motion (state changes fade; doors do not swing on every probe;
  nothing bounces); no gradients for their own sake except in thumbnails and the light-spill cue above.
- State colours must pass contrast in both themes, stay distinct from door-paint colours, and always be paired with
  shape and text.
- Numbers (ports, latency, percentages) in tabular/monospaced figures (JetBrains Mono is bundled in the sibling
  project).

## Empty and first-run states

- No apps declared yet: lead with the observed tray — "We found 4 web servers running. Name the ones you care about."
- Nothing running and nothing declared: a short explainer with the two commands that matter (`hallway run …`, and the
  YAML path for adding an app by hand) and a link to the agent guide.
- Daemon unreachable (in fronted mode Caddy serves the fallback page): see `03`.

## Errors

YAML parse/validation errors appear in place — on the affected card, or as a banner for `config.yaml`/bookmark
files — with file path, line and message. Never a blank page.
