`hallway update`, `service install --refresh`, and `doctor`'s new checks.

- **`hallway update [--check] [--to <version|tag>] [--yes] [--force] [--json]`** installs the newest Hallway with the package manager you installed it with, restarts the daemon on it, and rolls back if it doesn't answer as the new version within 30 seconds. It asks first, and says up front what happens to your apps. On macOS and Linux they keep running, apart from any whose job the new version writes differently, which are restarted. On Windows, the running apps are stopped while it installs and started again afterwards. Without a terminal it needs `--yes`. `--check` only says what's available, and exits 0 either way. `--to` is the only way to a lower version. `--force` doesn't wait while Hallway is busy. New exit codes, for scripts: **5**, this install can't update itself (npx's cache, a checkout, a global folder you can't write to: it prints what to run instead); **6**, the update failed and the old version is running again; **7**, the rollback failed too (it prints the commands to run by hand); **75**, Hallway is busy. `hallway upgrade` works too.
- **`hallway service install` now restarts a daemon that's already running**, even when it's the same version, so a reinstall never leaves the old process serving. It used to restart it only when another version was answering.
- **`hallway service install --refresh`** rewrites the installed service in this version's format, keeping its data home, and restarts it. It exits 4 if nothing is installed. **`--port <n>`** sets `port:` in `config.yaml`.
- **`hallway service status`** repeats what the last `update --check` or `doctor` found: as `update` in `--json` (left out when there's nothing to say), and as a notice on stderr. It never asks the registry itself.
- **`hallway doctor`** also checks this Node against the version Hallway needs, how Hallway was installed, whether the daemon's service runs this install and the version it answers as, and whether a newer Hallway is out. That last one asks the npm registry; **`--offline`** skips it. **`doctor --json` changes slightly:** it now carries `version`, and a line that used to say `"status": "info"` now says `"status": "pass"` with `"info": true`, to match the CLI contract's schema. A daemon port held by something else is now the check `port`, not `daemon`.
