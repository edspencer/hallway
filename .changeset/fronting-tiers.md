Local domains without admin rights. `hallway setup` now offers three tiers, asked on a terminal or chosen with `--trust`: **No admin** (`--trust user`) trusts Hallway's certificate for your account only, so on macOS it asks just for your own Touch ID or password and needs no administrator (on Linux it uses your NSS database, which Chrome reads, with no prompt; links carry `:4443`); **System-wide** (`--trust system`) is the setup you know, and the one custom domains need; **No prompts** (`--trust none`) serves plain `http://<app>.localhost` and asks for nothing. On macOS, launchd now holds loopback ports 443 and 80 for Hallway in every tier, with small forwarders handing connections to Caddy, so there is no pf redirect any more and nothing another tool's firewall rules can switch off. Re-running `hallway setup` (with any `--trust`) moves a Mac set up by an earlier version off its pf redirect; that removal needs sudo once. Switching tier removes what the old one added. `hallway doctor` checks each tier, every link Hallway gives follows the tier's scheme and port, and `config.yaml` records it as `proxy.trust` (and `proxy.scheme`). From `npx`, setup on macOS now asks you to install Hallway first, since the forwarders run it.
